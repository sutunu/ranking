# TIER STUDIO

スマートフォンとPCで使える、ログイン不要のTierランキング作成アプリ。React / TypeScript / Vite、dnd-kit、IndexedDB、Cloudflare Pages Functionsで構成しています。

## 漫画・小説の表紙も同じ検索へ統合

アニメ検索にGoogle Books、Open Library、NDL→ISBN→openBDの書誌検索を並列で追加しました。書誌・巻ごとに候補を残し、同じ画像URLは重複除去します。「アニメ・漫画・小説のイラスト」が標準の作品検索で、「漫画・書籍の表紙」「小説・書籍の表紙」も選べます。候補には画像種別・取得元を表示します。Google BooksのGraphic Novelsは漫画として扱い、単にNovelという文字だけで小説に誤分類しません。巻数を許容した作品名の先頭一致を使い、同じ単語を含む無関係な本や明示的なfan fiction・非公式素材を除外します。メタデータの欠落まで画像内容を自動認定するものではありません。

書籍検索は成功時30分、画像なし／エラー時30秒のキャッシュと同時要求共有を使います。ホスト単位でインスタンス内20回/分に制限し、429/503時にはRetry-Afterを尊重して休止します。全世界のWorker間で共有される制限ではありません。APIの一部が失敗してもポスターや他の表紙を表示します。

画像プロキシにGoogle Books、Open Library、openBD配信ホストを追加。Open Library起点のときだけInternet Archiveの特定の表紙ZIP・画像パスへの正規転送を許可します。Archive全体の汎用プロキシにはしません。NDL書影の403やGoogle Booksの429は回避しません。

### 提供元・利用条件

- Google Books: https://developers.google.com/books/terms ／API利用・帰属表示を守り、書籍画像の権利を別途確認してください。
- Open Library: https://openlibrary.org/dev/docs/api/search 、 https://openlibrary.org/dev/docs/api/covers ／公開APIのメタデータ・表紙IDを使用します。表紙の著作権が放棄されているとは扱いません。
- NDL: https://ndlsearch.ndl.go.jp/help/api ／書誌のISBNを取得する用途で利用します。
- openBD: https://openbd.jp/ ／提供される書誌・表紙URLだけを使用し、出版社ページのスクレイピングはしません。書誌の存在は表紙利用許諾を意味しません。

追加候補も既存の出典・利用条件・公式性未確認の情報を保持し、`ANIME_REQUIRE_PERMISSION` と `ANIME_BLOCKED_SOURCES` に従います。個人利用・非営利でも自由転載許諾を得たとは表示しません。公式サイト等のキービジュアルやキャラクターイラストを無断収集する仕組みはありません。

Google Booksはこの環境では429です。自身のAPI枠を使う場合はCloudflare Pagesの暗号化シークレット `GOOGLE_BOOKS_API_KEY` を設定して再デプロイできます。値をGitやVITE変数、チャットに入れないでください。未設定でもOpen Library等が動きます。

[表紙の実検索・画像追加・PNG検証と未取得の詳細](docs/book-validation.md)を参照してください。今回実際に取得したのは海外版を含む漫画／書籍表紙と小説表紙であり、添付の日本語小説表紙そのものを取得したとは主張しません。再実行は `npm run test:books`（先にローカルサーバー起動）。`BASE_URL`・`BROWSER_EXECUTABLE_PATH`・`CASE_FILTER`・`REPORT_PATH`を指定できます。

既存のトリミング・ピンチ調整・ランク直接追加・自動保存・PNG出力はそのまま利用できます。画像の種類と年は任意メタデータとして追加保存し、旧ランキングの保存形式は保持します。

## 非破壊の画像調整と25作品検証

広告収益化は行わない方針です。広告コード・広告スペースはありません。非営利でも著作権と提供元規約を維持します。

- 画像編集メニューの「画像の表示位置を調整」で、2:3 / 3:4 / 1:1 / 16:9、左右上下、1〜4倍の拡大率を保存します。指でドラッグ、2本指のピンチ、スライダーに対応します。
- `.crop` は任意フィールドです。旧画像は中央・倍率1・2:3が既定。保存画像を切り抜いて上書きせず、表示パラメーターのみ変更します。追加時の画像正規化は最大辺1600px（旧640px）です。元のアップロードファイルとのバイト単位の同一性は保証しません。
- CSSのobject-fit / object-position / transformと、同じ幾何条件のCanvas切り出しを使用します。比率の異なるアイコンも行内に詰めて出力します。調整を保存すると枠いっぱい表示へ切替え、既存の縦横比維持表示へ戻すこともできます。顔や文字の自動検出機能はありません。中央切り抜きが不適切なら手動で補正してください。
- アニメの別名解決を一般画像メタデータ取得から分離。リダイレクト・言語間リンクを並列で解決し、15分/200検索の別名キャッシュ、15分/1000作品の別名索引を追加。正式名・英語名・ローマ字・別名が一致した取得済み作品はAPIを再検索せず再利用します。メモリキャッシュであり永続DBや完全な作品全集ではありません。
- 候補の放送年・形式・別名、画像代替URLを取得します。関連度が同じ場合は古い原シリーズを先に表示します。版・シーズンは別作品のまま保持します。AI生成や非公式イラスト等の明示的メタデータも除外しますが、画像内容をAI認定する機能ではありません。

[25作品の正式名・別名・出典・検証結果](docs/anime-25-validation.md)を参照してください。検索25/25、画像取得25/25、追加・保存復元25/25。母集団を限定した測定であり、全アニメの網羅率ではありません。100作品検証は未実施です。旧年代作品は1963〜1995年も含みます。

テスト: `npm run test:crop` はスマホ相当の2本指ピンチ・非破壊調整保存・再読込・PNG内の実ピクセルを検証します。`npm run test:anime` は25作品と別名を実検索します。外部API負荷を考慮し繰り返し実行を抑えてください。ブラウザテストは独立したコンテキストで動き、利用者の保存領域を削除しません。

公式サイトの再利用許諾を持つキービジュアル配信フィードはないため、現在の実候補は作品DB登録ポスターです。公式画像・商用転載可能などと認定しません。利用不可と判明した素材は除外設定で停止できます。TMDBはキー未設定でアニメ検索には未統合のままです。

## アニメ検索の統合強化

AniList・Kitsu・Jikanを並列に検索し、部分名・日英名・ローマ字・別名をWikipediaの正式名リダイレクト／言語間リンクと各DBの別名・synonymsで解決します。個別作品を手登録した辞書はありません。候補不足時は別の表記で再検索します。共通MAL ID、または厳密なタイトル・年・形式の一致でまとめ、TV版・続編・映画は保持します。同一作品の異なるDB画像は選択候補として残します。

プロバイダー別キャッシュは15分、エラーは30秒、検索応答は5分。実行中の同一要求は共有し、各APIはインスタンス内40回/分まで。Jikanは直列化して350ms間隔を置きます。全世界で共有するレート制限ではないため、大規模運営にはKV等による集約制限が別途必要です。外部APIの失敗で検索全体を停止しません。

画像ごとに作品ID・出典・API規約URL・公式性確認状況・再利用許諾状況を追加保存します。古い保存データのフィールドは変更しません。作品未発見、画像なし、通信失敗、許諾未確認を識別し、画像読み込み失敗は画面で案内します。画像なしでも作品名を表示します。`anime_search`の構造化ログには検索語・プロバイダー・使用別名・HTTP結果・件数を記録します。クエリを含むため運営時のログ閲覧範囲と保存期間に注意してください。

### 権利と収益化

公式サイトの無断スクレイピングはしません。公式画像フィード等の再利用許諾がないため、現状の候補はDB登録ポスター（優先順位4）です。公式サイト由来の公認キービジュアル／ジャケットを自動取得したとは扱いません。`officialVerification=unverified`、`reuse=permission_not_confirmed`を明示します。APIの無料利用や取得成功は画像の著作権許諾を意味しません。AdSense導入に適合・商用利用可能と認定したものではありません。

- AniList規約: https://docs.anilist.co/guide/terms-of-use
- Jikan API: https://docs.api.jikan.moe/ （非公式MyAnimeList API、MAL公式連携ではありません）
- Kitsu API: https://kitsu.docs.apiary.io/

Cloudflare変数 `ANIME_REQUIRE_PERMISSION=true` は、許諾未確認候補を表示しない厳格モードです。現状すべてのDB画像が未確認のため、この設定では作品名のみ表示します。
`ANIME_BLOCKED_SOURCES` には削除対象の候補ID（例 `kitsu:7442`）／出典URL／画像URLを改行かカンマで設定できます。検索候補とキャッシュキーに反映します。端末内の既存画像やダウンロード済みPNGを遠隔削除する機能ではありません。削除依頼受付はサイト運営者が別途用意し、依頼の確認後に除外リストと必要な公開コンテンツを更新してください。

TMDBは既存の映画検索接続を維持しますが、アニメ統合検索へは追加していません。キーがなく実接続未確認です。API増加だけで公式素材や許諾を捏造しません。

[10作品と略称の実検証一覧](docs/anime-validation.md)を参照してください。再実行は `npm run test:anime`（先にローカルサーバー起動）、`BASE_URL`・`BROWSER_EXECUTABLE_PATH`で指定できます。生の実行結果は `artifacts/anime-matrix.json` へ保存します。特定作品の再試験は `CASE_FILTER`（`|`区切り）と`REPORT_PATH`で別ファイルに保存できます。

## 作品画像限定検索と直接ランク追加

基本デザイン・保存形式を維持し、検索結果をタップすると「どのランクに追加しますか？」を表示します。現在の全ランク・名前・色を反映し、選択後に閉じて直接追加します。未分類も選択可能です。アップロードとURL追加の既存動作は維持します。

アニメ・漫画・ゲーム・映画・キャラクターでは、候補不足をCommonsの一般写真で埋めません。一般ジャンルでもWikipediaの作品種別から判別できた場合は作品画像検索へ切り替えます。アニメ・漫画はAniListの `coverImage` とKitsuの `posterImage`、キャラクターはAniListの `image`、映画はTMDBの `poster_path`、ゲームはRAWGの `background_image` だけを使います。一般検索にもコスプレ・実写・ファンアート等の名称／メタデータ除外を適用します。メタデータの欠落や作品データベース側の誤登録まで画像内容を自動保証するものではありません。

画像には登録元の名称・作品名・出典を表示します。「作品データベースのポスター／カバー」等の表示は、登録された用途を示すもので、公式性や自由利用許諾を保証しません。独立した権利確認がない画像を「公式確認済み」と表示しません。RAWGの登録背景画像はパッケージ画像に限定されません。画像がなければ「適切な画像が見つかりません」と表示します。

### 映画・ゲームAPIを有効にする場合

現在のクラウド環境にTMDB／RAWGの認証設定はありません。接続コードと画像プロキシは実装済みですが、キー未設定時は映画／ゲーム候補を返しません。これらのライブ動作は未確認で、HTTPレスポンスを差し替えた自動テストで接続・変換処理を確認しています。

Cloudflare Pagesの設定 → 変数とシークレットで、必要なものだけ**暗号化シークレット**として追加し、再デプロイしてください。

- `TMDB_API_KEY`: TMDBのAPIキー。サーバーから映画検索に使用します。
- `RAWG_API_KEY`: RAWGのAPIキー。サーバーからゲーム検索に使用します。

`VITE_*`へ設定したり、Gitやチャットに値を保存しないでください。ローカルアダプターは同名のプロセス変数を読みます。`.dev.vars.example`は空欄の見本です。APIの利用条件・料金・商用利用資格を確認してから有効化してください。

- TMDB: https://developer.themoviedb.org/docs/faq （帰属表示、承認ロゴ、非商用・商用利用条件の確認が必要。商用ライセンスは別途。）
- RAWG: https://rawg.io/apidocs （プランごとの利用条件と帰属表示が必要。無料商用利用を一律に保証しません。）

キーを使う処理と画像プロキシはPages Functions内だけで実行し、ブラウザ・検索結果にキーを返しません。TMDBの帰属文は画像出典に含めています。運営者はサービスを有効化する前に、利用形態に応じたライセンスとサイトのTMDBロゴ等の帰属表示要件を満たしてください。

## v2：検索・ジャンル管理の改善

- 日本語・英語Wikipediaの検索インデックス、言語間リンク、検索候補補正を使い、略称・部分名から正式名を解決。かな・全半角・英大小文字を正規化して関連度順に表示します。入力ミスへの対応は検索元の補正候補に依存し、任意の誤字を保証するものではありません。
- アニメ・漫画はAniList / Kitsu、一般ジャンルはWikipedia / Commons、食品はOpen Food Factsも組み合わせます。ジャンルは検索順位を優先するもので、対象を排他的に限定しません。検索欄で「一般検索に広げる」へ切替可能です。商品名の固定リストは使いません。
- 画像配信先の限定を維持し、許可済みホスト間のみ最大4回の転送を追跡。失敗時は検索元が提供する元画像等の代替URLを試行します。サムネイルも同じ画像取得経路で表示します。追加失敗は候補に表示し、別の候補を選べます。
- 任意ジャンルの作成・名前変更、作成時のジャンル選択、既存ランキングの移動、ジャンルとタイトルでの絞り込み。複製・削除・Undo/Redo等は維持します。
- 既存のIndexedDBキー `tier-studio-v1` を維持。旧データは初回移行前に `tier-studio-backup-v1` に原本を退避し、画像・ID・ランクを保持したまま `version: 2` とジャンル情報を追加します。ジャンル未設定は「その他」です。読み込み失敗時は自動保存を開始せず、元データのダウンロードを案内します。
- マイランキングの「すべてバックアップ」はジャンル一覧を含むJSONを出力します。旧JSON配列と新形式をどちらも復元可能です。

### APIの料金・利用条件

追加APIキーや有料サービスは使いません。Wikipedia / CommonsのAPIは無料ですが、画像の利用条件はファイルごとに異なります。作者・ライセンス名・ライセンスURL・出典ページ・加工情報を保持します。Kitsu / AniListの作品画像は権利者の著作物であり、API提供は画像の自由利用許諾を意味しません。

Open Food Factsは公開API（https://openfoodfacts.github.io/openfoodfacts-server/api/ ）。検索は10回/分の上限を前提に、結果の5分キャッシュ・候補件数制限・Workerインスタンス内で8回/分の食品検索制限を設けています。画像はCC BY-SA 3.0、データベースはODbLの条件に従い、画像クレジットと製品ページを保持します。配信許可ホストに `images.openfoodfacts.org` を追加しています。共通のキャッシュはWorkerインスタンス内に限られます。多数の利用者向けの集約レート制限は別途必要です。Cloudflare自体の利用枠・料金はアカウントのプランに依存します。

### 検証と残る制限

ビルド、サーバーを含むTypeScriptチェック、21件の自動テスト、Pages Functionsコンパイルを確認しています。Chromiumのスマホ幅・タッチイベントによる操作検証を行い、iPhone Safari実機は未確認です。利用者の実ブラウザ内データへはアクセスせず、既存画像を含む旧形式データを隔離ブラウザに投入して移行を検証します。

実検索で「フリーレン」「進撃」「鬼滅」「リゼロ」、商品画像で「じゃがりこ」「ハイチュウ」「ポッキー」「たけのこの里」「堅あげポテト」を確認しました。**「ピュレグミ」は商品そのものの画像を確認できていません**。関連画像が表示される場合があり、パッケージ写真の取り違えに注意してください。Open Food Factsは調査時503が断続的に発生しました。後続の検証でじゃがりこの味別商品の実検索に成功しましたが、安定稼働と全商品の取得は未確認です。全商品・全作品の画像や、全ての外部サービスの稼働を保証しません。特定商品の画像を偽装する登録や、メーカーサイトの無許可スクレイピングは行いません。

公開URL・Pagesプロジェクト設定は変更しません。既存のmain連携が有効ならGitHub反映後に同じサイトへ自動デプロイされます。公開サイトの実動確認はURLとデプロイ完了を確認してから行ってください。

## 開発

Node.js 24（この環境では24.22.1）、npmを使用します。

```sh
cd /workspace/ranking
npm ci
npm run build
npm test
npm run start:local
```

プロキシ対応のローカルサーバーがビルド済み静的ファイルと`functions/`と同じハンドラーを提供します。`HTTP_PROXY` / `HTTPS_PROXY`とCA設定を維持します。Cloudflareランタイムでのコンパイル確認には`npm run pages:dev`も使用できますが、このクラウド環境のWrangler内Workerは外部通信プロキシを継承しないため、実API検証には`start:local`を使います。`npm run dev`はUI単体の開発用であり、検索APIは提供しません。ソースを変更したら`npm run build`でPages用出力を更新してください。

ブラウザテスト:

```sh
npx playwright install chromium
npm run test:browser
# ジャンル移行・実商品画像の追加保存を検証（隔離ブラウザ）
npm run test:genres
# 既存Chromiumを使う場合:
BROWSER_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
```

実API・タッチ操作の検証は`npm run test:live`でも実行できます（外部APIへの通信が必要です）。

先にローカルサーバーを起動してください。`BASE_URL`でテスト対象を変更できます。テストは新しいブラウザコンテキストを使用し、利用者の保存データを消しません。検索の上流応答はテスト内で差し替えます。実APIの疎通テストとは別です。生成物は`artifacts/`に保存されます。

## 実装機能

- SS / S / A / B / C / D、ランク名・色・順番の変更、追加・削除。削除時の画像は未分類に戻ります。
- 画像の検索、端末からのアップロード、HTTPS画像URL入力。画像の追加・削除・名前変更・入れ替え、重複防止。
- dnd-kitによるマウス・長押しタッチドラッグ、同一ランク内の並び替え。画像をタップして移動先を選ぶ操作も可能。タッチは230ms長押しでドラッグ開始し、それまでは縦スクロールを優先します。
- ランキングタイトル、画像フィルター、未分類エリア、40操作のUndo / Redo、初期化。
- 複数ランキング、複製・削除・タイトル欄での名前変更。
- IndexedDBへの自動保存。端末・ブラウザごとの保存であり、別端末同期はありません。
- 画像を含むJSONの書き出しと復元。復元は既存データを上書きせず、新規ランキングとして取り込みます。
- 縦横比維持 / 統一サイズ表示切り替え。
- 全ランク・タイトル・出典を含む幅2800pxのPNG保存。ダーク / ホワイト背景。長いランクは折り返し、端を切りません。出力高さの上限は32000pxで、超える場合は分割を案内します。未分類と編集UIは含みません。
- PNG生成後の共有ボタンはWeb Share API対応端末で共有メニューを開き、非対応端末ではダウンロードします。

## 画像検索と権利

### AniList

`POST https://graphql.anilist.co`。アニメ作品名を日本語 / 英語で検索し、作品名・カバー画像・作品ページを取得します。成人向けフラグの作品を除外し、1回24件に制限します。APIキー不要。カバー画像の権利は各権利者に帰属し、検索結果には作品ページへのリンク、保存画像には出典を付けます。API利用と画像の再利用許諾は別です。公開・再配布前に利用条件を確認してください。

- API: https://docs.anilist.co/
- 利用条件: https://docs.anilist.co/guide/terms-of-use

### Kitsu（アニメ検索の代替）

AniListが失敗した場合は`https://kitsu.io/api/edge/anime`へ自動的に切り替えます。日本語タイトル、ポスター、作品ページを取得し、出典を保持します。成人向けフラグのある候補は除外します。APIキー不要。画像の権利は各権利者に帰属します。

- API: https://kitsu.docs.apiary.io/
- 作品情報: https://kitsu.app/

### Wikimedia Commons

`https://commons.wikimedia.org/w/api.php`のMediaWiki APIで幅広いジャンルを検索します。名称、サムネイル、作者、ライセンス名、出典ページを取得します。日本語検索に対応しますが、日本語のメタデータが少ない画像は英語で検索してください。ライセンス情報が取得できない候補は表示しません。作者・ライセンス・出典は画像と一緒に保存し、PNG下部にも記載します。出典ページで画像ごとの条件を確認してください。

- API: https://www.mediawiki.org/wiki/API:Main_page
- 再利用: https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia

TMDB / RAWG、漫画専用・人物専用APIは未接続です。それらのジャンルはCommons検索、URL入力、アップロードで利用できます。すべての作品・人物について画像が見つかる保証はありません。

### CORSと画像保存

検索APIはPages Functionsから呼び出します。検索画像は`/api/image`で取得し、ブラウザで最大辺1600pxのPNGに変換してIndexedDBへ保存します。PNG出力時は保存済みデータのみをCanvasへ描画するので、再取得や外部画像のCORSに依存しません。

画像プロキシはHTTPSの`upload.wikimedia.org`、`thumb.wikimedia.org`、`s4.anilist.co`、`media.kitsu.app`のみ許可し、リダイレクト、ポート指定、URL内認証を拒否します。画像MIME・15MB上限・タイムアウトも検査します。任意URLの公開プロキシにはしません。直接入力の他ドメイン画像は、そのサイトがブラウザCORS取得を許可する場合のみ対応します。失敗時はアップロードを案内します。SVGは受け付けません。GIFは静止画として追加されます。

画像は利用者が権利を確認して追加してください。出典やライセンスの保持だけで、すべての利用が許可されるわけではありません。

## Cloudflare Pagesへ公開

1. このリポジトリをGitHubへ反映します。
2. Cloudflareの **Workers & Pages → Create → Pages → Connect to Git** から`sutunu/ranking`を選びます。Production branchに`main`を指定します。フレームワークプリセットは`Vite`、ルートディレクトリは空欄（リポジトリ直下）にします。
3. ビルドコマンドを`npm run build`、出力ディレクトリを`dist`、ルートディレクトリをこのプロジェクトのルートに設定します。Nodeバージョンは24を指定します。
4. デプロイすると`functions/api/search.ts`と`functions/api/image.ts`も実行されます。単なる`dist`の静的アップロードではAPIが動かないので、Git連携またはWranglerを使います。
5. 検索・画像追加・PNG保存を公開URLで確認してください。

CLIを使う場合はCloudflare認証済みの端末で:

```sh
npm run build
npx wrangler pages deploy dist --project-name tier-studio
```

この実装にAPIキー・DB・ログイン設定は不要です。将来キーが必要なAPIを追加する際はPagesのシークレットへ保存し、ブラウザコードや`VITE_*`変数に入れないでください。

## 検証と制限

本番ビルド、モデル・API・保存移行の21件の自動テスト、Chromiumでの基本操作、390px幅の表示、タッチイベントによる長押しランク間移動と同ランク内の並び替え、実検索画像の追加とPNG出力を検証しています。iPhone Safari / Chrome実機の検証は未実施です。IndexedDBの容量は端末に依存し、保存失敗時は画面に表示します。プライベートブラウズ・ブラウザデータ削除には永続保存できません。大切な内容はJSONでバックアップしてください。保存画像は元画像を最大1600pxに縮小したもので、元データ以上の画質にはなりません。

通信許可後、Wikimedia Commonsの実検索・画像取得、日本語「進撃の巨人」のKitsu検索（19件）・画像追加・PNG保存が成功しました。AniListは上流側403のため、この環境ではKitsuへの代替動作を検証しています。ネットワーク制限がある環境では`graphql.anilist.co`、`s4.anilist.co`、`kitsu.io`、`kitsu.app`、`media.kitsu.app`、`commons.wikimedia.org`、`upload.wikimedia.org`、`thumb.wikimedia.org`を許可してください。Cloudflare本番環境での検索はデプロイ後に確認してください。

ログイン・クラウド同期・共同編集・任意API横断検索は未実装です。Cloudflareへの実際の公開操作もまだ行っていません。
